## Policy

Heavy render evidence belongs in release assets, keyed by `sha256`; git keeps
this manifest, the markdown narrative, the hashes and the small golden inputs.
A file is moved only after its asset URL exists and every document that names
it has been updated. The manifest row is the record that survives the move.

## Staged move (not executed)

1. Upload the file to a release asset or object store under its `sha256`.
2. Replace the markdown link with the asset URL; keep the manifest row.
3. `git rm --cached` the moved files, keeping the local copy until the links
   and the render evidence are verified.
4. Grep each basename under `docs/` and `tests/` and confirm zero broken links.
5. Commit the removal. A history rewrite
   (`git filter-repo --path-glob 'docs/**/*.mp4' --invert-paths`) is a
   separate, coordinated force-push and is **not** part of this pass.

Removing files from `HEAD` does not reduce clone size while the blobs remain
in history. Until that rewrite is approved, step 3 is tree hygiene only.

## Regrowth guard

`.gitignore` now ignores new `docs/evidence/**/*.mp4`, `*.mov` and `*.webm`.
Existing tracked files are unaffected; the rule stops the next render from
silently adding another 7.9 MiB video.
