### 2.3 Concorrenza e Colli di Bottiglia
- **N-01 (P0):** `FramebufferPool` usa un solo `std::mutex` (`framebuffer_pool.cpp:192,417`) per acquire/release/stats/arena-set. Sotto il lock: hit exact su `m_free[key]` (:197-215), poi **scan lineare best-fit su tutti i bucket** (:218-236), poi campionamento `m_arena_provider`. Ogni nodo del livello parallelo TBB acquisisce qui 1-2 volte a frame. La strumentazione esiste già (`m_lock_wait_us`, `m_lock_hold_wall_us`, `PoolLockHoldMeter`) — il costo è misurabile ma la struttura non è stata cambiata. **Alto impatto, rischio Alto** (lifetime `storage_transferable` + clear policy).

Con 80 nodi × 60fps = ~4.8k lock/s sullo stesso mutex per session. **Medio, rischio Medio.**
- **N-07 (S-05):** `render_compatibility_frames` invariato; demolizione già decisa e tracciata (`patches/README.md:59`). Serve solo una decisione di calendario, non analysis.

## 3. Confronto prima/dopo — 3 riscritture Data-Oriented

### Es.1 — FramebufferPool: fast-path lock-free per bucket esatto (N-01)
**Prima (`framebuffer_pool.cpp:192-236`):** ogni acquire di ogni nodo prende l'unico mutex, cerca la size-class esatta sulla map e, sul miss, scandisce linearmente tutti i bucket sotto lock.

**Dopo (pattern: per-bucket atomic stack, global mutex solo sul miss):**
```cpp
struct BucketFreeList {  // una per FramebufferPoolKey, pre-allocata
    std::atomic<Framebuffer*> head{nullptr};   // Treiber stack
    std::atomic<std::uint32_t> count{0};
};
// acquire_unique:
//   1. key = round_to_bucket(w,h) (già senza lock)
//   2. exact = buckets_[key]  → pop lock-free O(1); se ok → resize_logical fuori lock, done
//   3. solo su miss: std::lock_guard(m_mutex) → best-fit scan + arena provider (come oggi)
// release:
//   1. se !storage_transferable → global mutex come oggi
//   2. se transferable → push lock-free sul bucket; budget enforcement delegato
//      a un trim periodico (già esiste evict_global_lru) invece che inline
```
Zero allocazioni, ownership esclusiva per slot, il mutex globale resta solo come fallback raro. Acceptance: `m_lock_wait_us` ~0 in steady-state, `framebuffer_reuses` invariato, `framebuffer_pool_exact_hit` cresce. **Rischio Alto** va ridotto: tenere il best-fit scan sotto mutex invariato e gate la fast-path dietro flag per A/B con i counter già presenti.

### Es.2 — NodeMemoryTracker: batching thread-local (N-06)
**Prima (`node_memory_tracker.hpp:92-160` + `node_runner_single_node_detail.hpp:269-271`):** 1 lock_guard per `acquire_temporary`/`release_temporary`/`observe_node` per nodo per frame.

**Dopo (pattern: TLS batch + flush 1 lock/level):**
```cpp
struct NodeMemoryBatch {                       // thread_local, riusato
    std::array<BatchEntry, kMaxNodesPerLevel> entries;  // SoA piatto, no map
    std::size_t count{0};
    void record(std::string_view id, i64 live_delta, u64 bytes) noexcept;
};
thread_local NodeMemoryBatch tls_batch;
// per nodo: tls_batch.record(id, +bytes)   → zero lock, zero map, zero string
// a fine livello (dispatch_level_nodes, dopo for_each_index):
//   tracker.merge_batch(tls_batch);          → 1 lock per livello per thread
```
Il tracker mantiene la stessa SSOT (stesso valore aggregato osservabile — contract già testato da `tests/perf/test_node_memory_tracker.cpp`); cambia solo la granularità della contesa: 1 lock/level/worker invece di N lock/nodo. **Rischio Medio** (sincronizzare il flush con l'ordine di osservazione dei sample temporali).

### Es.3 — SSAA downsample: buffer dalla pool/arena (N-04)
**Prima (`helpers.hpp:71-100`, `composition.cpp:459-471`):**
```cpp
auto dst = std::make_unique<Framebuffer>(dst_w, dst_h);   // heap per frame
// ... box filter ...
return std::shared_ptr<Framebuffer>(out.release());
```
**Dopo (borrow dalla pool già thread-local visibile, zero heap steady-state):**
```cpp
[[nodiscard]] OwnedFB downsample_fb(cache::FramebufferPool& pool,
                                    const Framebuffer& src, i32 dst_w, i32 dst_h) {
    auto dst = pool.acquire_owned(dst_w, dst_h, /*clear=*/false);  // reuse
    // box filter identico su dst->data()
    return dst;   // ReturnToPool deleter esistente: zero churn
}
// call site: g_current_framebuffer_pool già impostato dal ProfilingGuard del barrier
```
`composition.cpp:469` diventa `out = downsample_fb(pool, *render_fb, w, h)`. Il consumatore finale è il returned `shared_ptr<Framebuffer>`: la conversione `OwnedFB → shared_ptr` con deleter ReturnToPool esiste già (`acquire_owned`). **Rischio Basso.**

## 5. Sintesi
Il grosso del debito P0 di FIXING.md è stato effettivamente pagato (heap churn per-pixel/per-glyph eliminato, fail-loud sul glyph atlas, doppio sha256 unificato, hash unificati). I due colli veri rimasti sono **strutturali e concentrati**: il mutex singolo della `FramebufferPool` (N-01) e l'upload-under-lock del glyph atlas sul miss (N-02) — entrambi già instrumentati e con il disegno del fix già presente nei commenti del codice. Il finding **nuovo** più importante è di affidabilità, non di performance: la fase mesh che sotto `WarnAndSkip` dichiara successo con un asset required corrotto (N-03) — un fallimento silenzioso in un codebase che altrove ha fatto dell'eliminazione dei fallback silenziosi una regola di governance.
